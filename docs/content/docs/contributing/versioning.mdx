---
title: Versioning
description: How version numbers are computed from git.
---

`src_method` follows [semantic versioning](https://semver.org/) and
[PEP 440](https://peps.python.org/pep-0440/). Version numbers are computed from
git by [`hatch-vcs`](https://github.com/ofek/hatch-vcs), which wraps
[`setuptools-scm`](https://setuptools-scm.readthedocs.io) and its [default
scheme](https://setuptools-scm.readthedocs.io/en/latest/usage/#default-versioning-scheme),
so every revision on every branch has an unambiguous version. The build writes it
to `src/src_method/_version.py`, which is generated and never edited by hand.

The version is available as `src_method.__version__` and looks like
`0.3.3.dev31+gdaa652023.d20261006`:

- `0.3.3` is the latest tag with its last component increased by one: the
  release being worked towards.
- `.dev31` is the number of commits since that tag.
- `+gdaa652023` is the short hash of the current commit.
- `.d20261006` is added only when the working tree has uncommitted changes.

While in `0.x.y`, breaking changes may occur in minor releases. Commit types
drive the bump: `feat` is a minor change, `fix` a patch, and a `!` marks a
breaking change.
